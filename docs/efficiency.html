What the cache actually changes

One mechanism (skip the re-read on a hit) and one measurement (6,603 real tool calls replayed from five Claude Code sessions on the dfos project). No projections below — every number came out of the replay.

The mechanism

Same two hops either way — an agent calling a read tool against a source. The cache doesn't change the hops; it adds a branch that skips both of them on a hit.

CAUTION

Raw repeat-count is not the same as safe-to-cache. The most literally-repeated Bash commands in this dataset were git status --short (17×) and git push origin main (9×) — both re-run on purpose, because the point is checking current state. Serving those from cache wouldn't save tokens, it would serve a lie.

nowhereman's own guidance (AGENTS.md, the nowhereman-cache skill) routes only idempotent, read-only tools — Read, Grep, Glob, WebFetch, WebSearch — through the cache, and leaves Bash out by default.
